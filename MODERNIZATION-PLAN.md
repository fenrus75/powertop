# PowerTOP C++ Modernization Plan

Generated by a guided modernization pass following `protocols/cpp-modernization.md`
(from the corporate `corp-cpp.instructions.md` rule pack), Mode 4.

## Session parameters (decided with the user before Phase 1)

- **Target standard:** C++20 (no change from current `meson.build` `cpp_std=c++20`).
  The Phase 0 C++23 opportunity scan found no CRTP, no hand-rolled backtrace
  code, and no sorted-vector-as-map patterns in `src/`; the printf/iostream
  usage found is better served by the project's existing `pt_format`/
  `std::format` i18n convention than by `std::print`. Not a compelling case
  for a dialect uplift at this time.
- **ABI guarantees:** None. PowerTOP builds a single `executable()` target
  (no `shared_library()`, no installed/exported headers) — confirmed by
  grepping `meson.build` and `src/`. Phase 2's wrapper-preservation policy
  for externally-visible functions therefore does not apply; signatures may
  be changed in place when a candidate requires it.
- **ASan-by-default test protocol:** Not applicable — `build_acov`
  (`-Denable-tests=true -Db_coverage=true -Db_sanitize=address`) already
  exists per `release-checklist.md` and is part of the release process.
- **Scope:** Full `src/` tree (137 files, ~26,270 lines).

## Phase 0 baseline

- Compilers available: g++ (Debian 16.2.0), clang++ (Debian 21.1.8) — both
  support `-std=c++23` if ever revisited.
- Tools available: `cppcheck` and `clang-tidy`, both installed.
- Baseline test suite (`ninja -C build_tf test`): **61/61 passing.**
- Tool scan commands used:
  - `cppcheck --enable=all --inconclusive --std=c++20 -I src src/`
  - `run-clang-tidy -checks='-*,modernize-*' -quiet 'src/.*\.cpp$'` (from `build_tf/`)

## Tiering

| Tier | Content | Example corp-cpp rule labels |
| :--- | :--- | :--- |
| A — Security-critical | Raw C strings and buffers | No Raw C Strings, Size Parameters, Banned C String Functions, Checked snprintf, Integer Conversions |
| B — RAII / lifetime | Manual resource and ownership management | No Naked New, RAII Resources, Rule of Zero/Five, View Lifetime, Scoped Locks |
| C — Idiomatic modernization | Correct-but-dated code | Range-Based Loops, Type Deduction, Retrofit Specifiers, Explicit Constructors |

Within each tier, items are ordered by risk-reduction-per-effort (trust-boundary
reachability first, then smallest blast radius).

**A8 remaining sites — intentionally kept as C arrays:**
- `src/perf/perf_bundle.cpp:141` — `unsigned char data[0];` is a C flexible-array-member
  idiom for variable-length kernel trace records; `std::array` cannot represent this.
- `src/tuning/bluetooth.cpp:71,90,97` — `bdaddr_t`/`struct hci_dev_info` mirror the
  kernel/bluez binary layout used by `ioctl(HCIGETDEVINFO, ...)`; must stay exact-layout
  C arrays to match the kernel ABI.
- `src/main.cpp:95` — `struct option long_options[]` feeds `getopt_long()` directly via a
  C-idiom all-zero sentinel terminator; `std::array`/CTAD doesn't cleanly express this
  nested-aggregate shape, and there's no safety benefit to forcing it.
- `src/cpu/intel_cpus.cpp:47` — `intel_cpu_models[]` is scanned with a `!= 0` sentinel
  loop; converting to `std::array` would require removing that idiom and verifying no
  legitimate `IFM()` value is ever `0` — judged not worth the risk for a mechanical pass.
- `src/calibrate/calibrate.cpp:205,206` — `buffer[64*1024]` (raw `read()`/`write()`
  syscall buffer) and `filename[]` (mutated in place by `mkstemp()`) — left as-is; the
  `mkstemp()` mutable-buffer contract makes a container conversion more awkward than
  beneficial here.
- `src/measurement/extech.cpp:66,67` — `struct packet { char buf[256]; char op[32]; ...}`
  used with raw `read()` and sub-buffer address-of-element access; left as C arrays since
  the struct is used as a POD wire-format buffer for the serial protocol.
